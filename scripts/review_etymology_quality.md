# 한자 풀이 품질 검토 보고서

## 🚨 심각한 문제점

### 1. **절단된 영문 정의 (Critical)**
대다수의 부수가 영문으로만 부분적으로 표시됨. 사용자가 이해할 수 없음.

**예시:**
- Line d10_Top.md:14: `危(dangerous,)` ← "dangerous"로 절단
- Line d10_Top.md:25: `囷(a round bi)` ← "a round building" 추정, 절단됨
- Line d10_Top.md:46: `帛(silk, fabr)` ← "silk, fabric" 추정
- Line d10_Top.md:57: `吕(a musical )` ← "a musical note" 추정
- Line d10_Top.md:78: `尧(a legendar)` ← 절단됨

**발생 원인:** Make Me a Hanzi의 definition 필드가 truncate되고 있음
**심각도:** ⭐⭐⭐⭐⭐ (매우 높음)
**영향:** 약 30-40%의 부수 설명이 불완전함

---

### 2. **"?" 기호 그대로 노출 (Critical)**
부수 분해 불가능한 경우 "?"을 그대로 표시.

**예시:**
- d01_Top.md, Line 14: `？ + 一(한 일)` ← 与의 첫 부수가 불명
- d01_Top.md, Line 24: `丶(점 주) + ？` ← 之의 두 번째 부수가 불명
- d01_Top.md, Line 104: `？ + 月(달 월)` ← 有의 첫 부수 불명
- d10_Top.md, Line 131: `士(士 (부수, 11자)) + ？` ← 声의 부수 불명

**발생 원인:** MMH의 decomposition 데이터가 불완전함
**심각도:** ⭐⭐⭐⭐ (높음)
**영향:** 약 5-10%의 한자가 부분적으로 분해되지 않음

---

### 3. **Decomposition 기호 노출 (High)**
사용자가 이해할 수 없는 Unicode 조합 기호가 그대로 노출됨.

**예시:**
- d10_Top.md, Line 79: `⿱ + 旦(dawn; morn) + 寸(치 촌)` ← "⿱"는 상하결합 의미
- d10_Top.md, Line 151: `⿸ + 卩(인장 절) + 又(또 우)` ← "⿸"는 좌측감싸기 의미
- d10_Top.md, Line 153: `⿰ + 口(입 구) + 口(입 구) + 犬(...) + ⿰ + 口(입 구) + 口(입 구)` ← 매우 혼란스러움

**발생 원인:** decomposition 기호를 한글로 변환하지 않고 그대로 노출
**심각도:** ⭐⭐⭐ (중간-높음)
**영향:** 약 15-20% 파일에서 나타남

---

### 4. **부수명 부정확 또는 누락 (High)**
일부 부수의 한글명이 부정확하거나 placeholder로 표시됨.

**예시:**
- d10_Top.md, Line 56: `青(青 (부수, 7자))` ← 한글명 부재, placeholder만 있음
- d10_Top.md, Line 185: `豆(豆 (부수, 9자))` ← 한글명 없음, "豆(콩 두)" 또는 "豆(네 숨 두)" 이어야 함
- d01_Top.md, Line 64: `二(二 (부수, 14자))` ← "二(둘 이)" 또는 "二(두 이)"여야 함
- d01_Top.md, Line 125: `麻(麻 (부수, 5자))` ← "麻(삼 마)"여야 함

**발생 원인:** radical_map에 이들 부수의 한글명이 부재하거나 placeholder로 업데이트됨
**심각도:** ⭐⭐⭐⭐
**영향:** 약 20-25% 파일에서 나타남

---

### 5. **다자 단어의 혼란스러운 표시 (Medium)**
다자 단어에서 각 한자의 부수가 구분되지 않음.

**예시:**
```
### 902. 细菌 / xì jūn / [명사] / bacterium; germ
- 한자 풀이:
  - 纟(실 사) + 田(밭 전)      ← 어느 한자?
  - 艹(풀 초) + 囷(a round bi)  ← 어느 한자?
```

**올바른 형식:**
```
- 한자 풀이:
  - 细: 纟(실 사) + 田(밭 전)
  - 菌: 艹(풀 초) + 囷(곡식 보관소)
```

**발생 원인:** 다자 단어에서 한자별 구분 표시 부재
**심각도:** ⭐⭐⭐
**영향:** 모든 다자 단어 (약 40% 이상)

---

### 6. **참고: s01_인사와_소개.md와 비교**

**예상된 형식:**
```
### 8. 认识 / Rènshi / [동사] / 알다, 알게 되다

- 한자 풀이:
  - 认: 讠(말씀언변) + 人(사람인) → 말로써 사람을 알아보다
  - 识: 讠(말씀언변) + 只(다만지) → 말로써 알다, 식별하다
```

**현재 생성 형식 (부족):**
```
### ~~. 认识 / ...
- 한자 풀이:
  - 讠(말씀언변) + 人(사람인)
  - 讠(말씀언변) + 只(...)
```

**차이점:**
- ❌ 각 한자가 어느 것인지 명확하지 않음
- ❌ "→ 의미" 부분이 없음
- ❌ 어원 설명이 없음

## 💡 개선 방안

### 필수 (Critical)
1. **영문 definition 완성**
   - MMH dictionary.txt에서 전체 definition 추출
   - 또는 한글로 번역해서 표시

2. **"?" 처리**
   - "부수 분석 진행 중" 또는 건너뛰기
   - 수동으로 부수 추가 조사

### 권장 (High)
3. **부수명 완성**
   - radical_map 업데이트로 모든 부수 한글명 추가
   - "부수(부수명)" 형식 일관성 유지

4. **다자 단어 개선**
   - 각 한자별 명확히 구분: "한자: 부수(명) + 부수(명)"

5. **기호 처리**
   - ⿰ ⿱ 등의 기호를 "좌우결합", "상하결합" 등으로 변환

### 선택 (Medium)
6. **어원 정보 추가**
   - "→ 의미/어원" 부분 추가 (현재는 없음)
   - LLM 또는 사전 활용
